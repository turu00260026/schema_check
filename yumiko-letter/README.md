# ユミ子「未来の私からの手紙」

未来のユミ子から「今日も冴えないユミ子」へ、毎日1通。
コマンド1つで、その日の **フィード画像・Threadsキャプション・リール台本・全部入りテキスト** が `out/YYYY-MM-DD/` に出ます。
入力欄はありません。打つ文字はゼロ。開いて貼るだけ。

ユミ子の人格は `C:\ClaudeCode\yumiko\CLAUDE.md`（正）に従っています。`src/persona.js` はそれを「未来のユミ子が手紙を書く」形に組み替えただけで、キャラ設定は上書きしていません。

## 最初の一度だけ

```bat
cd yumiko-letter
npm install
npx playwright install chromium
setx ANTHROPIC_API_KEY sk-ant-...   （新しいコマンド窓を開き直すと効く）
```

Playwright はフィード画像を PNG にするためだけに使います。入れなくても動き、その場合は `feed.html` をブラウザで開いてスクショになります。

## 毎日

```bat
run_letter.bat
```

または `node make_letter.js`。終わると `out\2026-09-10\` のようなフォルダが開きます。

| ファイル | 中身 | 使い方 |
|---|---|---|
| `feed.png` | 便箋デザインの手紙画像 1080×1350 | そのまま貼る |
| `caption.txt` | Threads用キャプション＋タグ | 全部コピーして貼る |
| `reel.md` | 15〜30秒のリール台本。秒数・テロップ・読み上げ文 | 短い版か全文版、おすすめが書いてある方を使う |
| `post.txt` | 上の全部入り | 迷ったらこれだけ開く |
| `feed.html` | 画像の元 | PNGが作れなかった日に開いてスクショ |
| `letter.json` | 手紙の素データ | 触らなくていい |

同じ日に2回実行しても同じ手紙が出ます。書き直したいときだけ：

```bat
node make_letter.js --again
```

そのほか：`--sample`（APIを呼ばず見本で動作確認）、`--no-png`、`--date 2026-09-10`（日付指定、テスト用）。

## 毎朝、勝手に届くようにする（Windows タスクスケジューラ）

管理者でなくてよいコマンド窓で、パスを自分の環境に直して1回だけ：

```bat
schtasks /create /tn "YumikoLetter" /sc daily /st 06:30 /tr "\"C:\ClaudeCode\yumiko-letter\run_letter.bat\""
```

6:30 に手紙が生成され、フォルダが開きます。止めたいときは `schtasks /delete /tn "YumikoLetter"`。

## 設定（`config.json`）

- `model`：既定 `claude-opus-5`。安くしたいなら `claude-sonnet-5`
- `effort`：既定 `medium`
- `recentScenesToAvoid`：直近何通の「場面」「一手」を渡してかぶりを避けるか（既定14）
- `threadsTag`：キャプション末尾のタグ。Threads はトピックタグ1つなので1つだけ
- `handle`：画像左下に出す文字。空なら `#タグ` が出る。Threads の新アカ名が決まったら入れる
- `image`：便箋の色・フォント。`accent` が封の色
- `reel.secondsPerChar` / `pauseSeconds` / `maxSeconds`：台本の秒数計算

## 中身の決まりごと

- **褒めない・励まさない・説教しない。** 未来の日常を軽く語り、「で、今日はこれ」と一手を1つ投げるだけ
- **今日の一手は15〜30分以内、貼るだけ・押すだけ・見るだけ・やめるだけ。** 計画・記録・振り返りは頼まない。新しくお金を使わせる一手も出さない
- **事実ルール。** 実在の商品・金額・実績は、`src/persona.js` の「確認済みの事実」にあるものだけ。確認していないことはぼかさず書かない。未来の収入は金額で誇示しない
- **垢バン対策。** 収益額の誇示、健康・医療の断定、リストにないサービス名やURLは禁止。外部リンクはキャプションに入れない（noteのURLは事実リストにあるが、手紙には毎回は出さない）
- **この仕組みは投稿しない。** 旧アカが飛んだ原因は「AIに投稿まで全部自動でやらせていたこと」と見ている（2026-09-10 つるさん談）。だから生成までは自動、**投稿は必ず人の手**で行う。投稿APIやブラウザ操作の自動化は今後も足さない。同じ時刻ぴったりに毎日投稿しない、投稿直後に機械的にいいね・フォローを回さない、も同じ理由
- **つるさん本人の作品（経理の魔王様など）は登場させない。** ユミ子の副業は note・セルフバック・生活費見直しで、ここにブラウザゲームが混ざるとキャラが割れる。混ぜたくなったら `src/persona.js` の確認済みリストに足せば書けるようになる

## 引き継ぎ資料で未決だった点の扱い

| 未決事項 | ここでの決め |
|---|---|
| 便箋のビジュアル | 生成り紙・紺寄りの墨・封の赤。アバター絵はまだ無いので載せていない。`config.json` の `image` で色替え可 |
| リールの絵 | 便箋の静止画＋テロップ。口パクは使わない |
| ナレーションの声 | 台本は AI音声でも本人の声でも読める形。秒数は1文字0.24秒で機械的に出している |
| 投稿頻度 | 生成は毎日1通。フィードは毎日、リールは台本だけ毎日出るので週2でも毎日でも選べる |
| つるさん作品をユミ子副業に混ぜるか | 混ぜない（上記） |
| 旧アカが飛んだ理由 | AIによる全自動運用が原因と推定。内容の問題ではないので `persona.js` は変えず、「投稿は人の手」を上の決まりごとに追加 |

## 仕組み

`make_letter.js` → `src/generate.js`（Claude API、構造化出力でJSON）→ `src/outputs.js`（キャプション・台本・HTML）→ `src/render.js`（Playwright で PNG）。
`out/history.json` に直近の場面と一手だけを溜め、次回のプロンプトに「かぶらせないこと」として渡します。手で編集するものではありません。

安全分類でモデルが手紙を断った場合は、サーバー側フォールバックで別モデルに自動で流します（`server-side-fallback` ベータ）。ベータが使えない環境では通常経路で出し直します。
